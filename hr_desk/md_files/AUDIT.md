# Stylo HR assistant audit

This records the code and database inspected before the fixes. Historical replies came from the reported tests. Their exact prompt, passages, and provider finish reason were unavailable.

1. **CONFIRMED — Retrieval and allowance accuracy.** The General Manager's daily allowance rate of Rs. 1,800 and its 300 km round-trip condition were both in PostgreSQL at “6. Daily Allowance.” The personal answer takes the matching table row and drops the surrounding rule (`backend/app/pipeline.py:733–789`). The historical claim that the model missed the row is **SUSPECTED**. In the current path the application can answer directly without calling the model. Ingestion preserves table rows, heading paths, content types and source dates. Text splitting caps passages at 3,200 UTF-8 bytes with up to 400 bytes of overlap (`backend/app/passages.py:993–1040,1378–1410`). `text-embedding-3-small` produces 1,536 dimensions by default (`backend/app/config.py`, `backend/app/llm.py:105–119`). Hybrid ranking combines keyword and vector candidates (`backend/app/retrieve.py:34–118`). The model normally receives up to four selected passages for a topic. Database filters enforce current effective dates, publication, supersession, and allowed roles (`backend/app/store_pg.py:436–531,594–642,678–712`).
2. **CONFIRMED — Named pay protection starts with the question.** A recognized named-pay request is refused before retrieval, and search scope comes from the signed-in employee (`backend/app/guardrails.py:62–75`, `backend/app/main.py:671–679`, `backend/app/store_pg.py:312,594–642`). Uploaded evidence on an otherwise allowed topic can still contain individual pay. The retrieval filters do not inspect passage text for it.
3. **CONFIRMED — Topic splitting exists, with gaps.** The six-item example already splits in the current code. Deterministic splitting handles commas and recognized conjunctions, with a cheap model fallback for explicit separation cues. The pipeline retrieves per topic, applies access scope, and groups and deduplicates evidence under a shared 12,000-byte budget. “DA” is missing from the deterministic topic recognizer, and unavailable topic replies use inconsistent wording (`backend/app/topics.py:13–91`, `backend/app/pipeline.py:129–141,590–732,883–916`, `backend/app/prompting.py:98–110`).
4. **CONFIRMED — Truncated answers can be returned.** Chat completions are buffered, with token caps and no custom stop sequence. The wrapper reads content without checking the provider finish reason. Some post-processing paths can also leave a partial fixed reply. Whether either caused the reported missing “Ask HR.” is **SUSPECTED** (`backend/app/llm.py:198–260`, `backend/app/config.py`, `backend/app/sanitize.py:46–100`).
5. **CONFIRMED — Evidence and history are interpolated into plain-text fields.** They are passed as user data with prompt instructions, but headings and delimiter-like strings in content are indistinguishable from application framing. The model can still follow malicious text, so permission enforcement must stay in the application (`backend/app/prompting.py:66–110`).
6. **CONFIRMED — Marker checks miss paths that bypass generation.** Model output has a marker check, but deterministic, recalled, or cached answers can reach the final response without that same check (`backend/app/sanitize.py:18–49`, `backend/app/pipeline.py:811–855`).
7. **CONFIRMED — Operational records duplicate policy text.** INFO logging does not directly log question bodies. Error stack traces can include provider exception details. The admin question record stores questions and answers intentionally, alongside copied citation bodies and image references. Questions are retained for three months (`backend/app/main.py:61–62`, `backend/app/pipeline.py:560–562,689–710,854`, `backend/app/store_pg.py:802,934–958`, `backend/app/operations.py:349`).
8. **CONFIRMED — The current prompt fills both placeholders.** The source is `system.md`. The file is read and rendered before answer generation. Other chat-model calls receive the same server-supplied date and designation through the request context. The designation comes from the employee linked to the session, with an explicit `unknown` fallback. The renderer rejects unresolved placeholders. Embedding and moderation use separate APIs. Which prompt version generated the reported historical replies is **SUSPECTED** (`backend/app/prompting.py:21–63`, `backend/app/pipeline.py:86–88`, `backend/app/main.py:671–679`, `backend/app/llm.py:241–258`).
9. **CONFIRMED — Chat history can steer the topic without granting permissions.** The server loads owned, bounded history. Rewrite uses up to six recent messages subject to a byte budget. The answer can also receive a selected prior question for context. History does not set the authenticated designation or replace SQL access filters (`backend/app/main.py:651–679`, `backend/app/operations.py:350–410`, `backend/app/rewrite.py:63–79`, `backend/app/llm.py:148–162`).

## Status after fixes

1. **Fixed — Deterministic answers and fixed replies.** The personal daily allowance uses the signed-in designation's row and gives the policy's 300 km round-trip condition, full and half rules, weekends and public holidays, and sponsored-travel exceptions. Eligibility remains conditional. Missing topics and missing rates use the shared replies in `backend/app/replies.py`. For an explicitly restricted multi-topic request, the app gives one fallback line per topic, even when all are restricted. A wholly unsupported request uses the full fallback. See `backend/app/pipeline.py` and `backend/app/prompting.py`.
2. **Fixed — Final answer guard and incomplete responses.** All fresh, saved, deterministic and recalled replies pass through `Pipeline._finish` before document references are removed. Matches on the marker, internal phrases, annexure references, or recognizable file paths return the fixed refusal. The guard logs only the trace ID. Any non-normal model finish becomes the complete fallback, including for a grouped answer with some deterministic results already prepared. See `backend/app/sanitize.py`, `backend/app/llm.py` and `backend/app/pipeline.py`.
3. **Partially fixed — Abbreviations.** DA, PF and FIR were taken from indexed policy terminology and are now normalized before retrieval. TA is an employee-facing alias for the business travel policy. The index did not contain standalone TA, OPD, or mediclaim. Updating the vocabulary still requires updating the reviewed mapping in `backend/app/topics.py`. No automatic discovery from later uploads was added. Per-topic top-k and evidence deduplication use the existing implementation.
4. **Partially fixed — Named pay in retrieved evidence.** The deterministic screen drops recognized named salary requests, records and earning statements before answer generation, regardless of the question. If the screen removes every relevant passage, the app treats the topic as missing. This is a heuristic. Unusual formatting, abbreviations, and indirect references can evade recognition. A persisted ingestion flag was left out because it would require a schema change and backfill and would not eliminate the need to screen old and new text at request time. See `backend/app/guardrails.py` and `backend/app/pipeline.py`.
5. **Fixed for the requested controls — Prompt-input hygiene.** Policy and history fields are JSON-serialized. Recognized control headings and standalone override directives are stripped before interpolation. Policy text and past messages can still influence model wording, so the database and application continue to enforce authorization independently. See `backend/app/prompting.py`, `backend/app/llm.py` and `backend/app/store_pg.py`.
6. **Fixed — New trace storage and error logs.** New traces store passage IDs, titles and labels instead of excerpt or image copies. On-demand resolution in the HR Questions screen enforces present-day publication, dates and the requesting admin's permissions. Legacy label-only records remain readable, and old trace payloads were not rewritten. Admin question traces expire after **three calendar months**. This is a fixed SQL interval, with no environment setting. Employee conversation storage has a separate 30-day code setting. Request, pipeline and worker error handlers record the class, request or job identifier where available, and status without provider bodies or stack traces.
7. **Partially fixed — Answer length.** The single-topic prompt targets 40 words and the eval runner measures selected answers. There is no programmatic truncation. The daily allowance retains all the requested conditions even when this exceeds the target. See the measured output in `HARDENING-VERIFICATION.md`.
8. **Fixed — Regression coverage for the specified scenarios.** Unit and live checks cover the six-topic order and role boundary, abbreviations, designation claims, topic switches, effective dates, allowance conflicts, named pay and injection screening, truncation, fixed replies and on-demand trace resolution. Provider truncation and conflicting policies were exercised with controlled fixtures. A rollback-only PostgreSQL test independently verified the active/expired/future filter.
